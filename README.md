# HTU 홈페이지 관리자 (Next.js 14 · Supabase · Vercel)

```
Vercel 주소 (예: https://htu-cms.vercel.app)
 ├─ /            → 관리자 페이지로 자동 이동
 ├─ /admin       → 관리자 (로그인 필요)
 └─ /api/public  → 기존 사이트가 내용을 받아가는 주소

기존 사이트 (https://htuglobal.com — 지금 서버 그대로)
 ├─ js/htu-cms-config.js → 관리자 연결 주소 (사이트 전체가 이 파일 하나 사용)
 ├─ menu3.js · js/footer.js → 기존 디자인 그대로, 메뉴·푸터를 관리자 데이터로 표시 (모든 페이지)
 ├─ index.html   → 홈페이지 (관리자에서 받은 파일로 교체)
 ├─ news.html    → News & Event 목록 / 내부 작성 글
 ├─ notice.html  → 공지사항 목록 / 상세 (첨부파일)
 └─ event.html   → 이벤트 목록 / 상세 (진행중·예정·종료 자동, 신청 버튼, 첨부파일)

회사소개·대표 인사말·비전·오시는 길 등 기존 서브 페이지는 HTML 수정 없이 menu3.js / footer.js 교체만으로 연동됩니다.
```

Vercel에서는 **관리자 페이지만** 열립니다. 사이트 화면은 기존 서버에서 그대로 서비스되고, 내용만 관리자에서 받아옵니다.

## 1. 설치 (환경변수 입력 없음)

1. **GitHub** — 이 폴더를 Vercel 에 로그인한 GitHub 계정의 새 저장소에 올립니다.
   ```bash
   git init && git add . && git commit -m "HTU CMS"
   git branch -M main
   git remote add origin https://github.com/<계정>/htu-cms.git
   git push -u origin main
   ```
2. **Vercel** — Add New → Project → 저장소 선택 → **Deploy** (환경변수 칸은 비워둡니다).
3. **Supabase 연결** — Vercel 프로젝트 → **Storage** 탭(또는 Integrations) → **Supabase → Connect**
   → 사용할 Supabase 프로젝트 선택(없으면 새로 만들기, Region: Seoul) → 연결 후 **Deployments → Redeploy**.
   Supabase 주소 · 키 · DB 주소가 Vercel 에 자동으로 들어갑니다. 직접 복사할 필요가 없습니다.
4. **Vercel 주소로 접속** → `관리자 처음 설정` 화면이 열립니다.
   - ① Supabase 연결 확인
   - ② **DB 자동 설치** 버튼 → 테이블과 현재 홈페이지 내용이 들어갑니다
   - ③ **대표 관리자 만들기** → 이름 · **아이디** · 비밀번호 입력 → 바로 로그인 (이메일 불필요)
   > 배포 직후 바로 진행하세요. 관리자가 아무도 없을 때 처음 가입한 사람이 대표 관리자가 됩니다.
5. **연동 설정** 메뉴에서 번역 엔진 API 키(Claude · DeepL · Google 중 하나)를 저장하면 자동 번역이 켜집니다.
   키는 Supabase 에 보관되고 다시 배포할 필요가 없습니다.

**DB 자동 설치 버튼이 없을 때** (연동에 DB 주소가 없는 경우): 처음 설정 화면의 `install.sql 내려받기` →
Supabase **SQL Editor → New query** → 붙여넣기 → Run. 이 파일은 새로 설치 · 업데이트 모두 처리하고 여러 번 실행해도 안전합니다.
(`supabase/install.sql` 과 같은 파일입니다. 예전처럼 schema · seed · migration 을 순서대로 실행할 필요가 없습니다.)

**예전 버전을 쓰던 경우**: 새 코드로 배포 → 대표 관리자로 로그인 → 대시보드의 `DB 업데이트 필요` 안내 → **연동 설정 → 자동 업데이트**.
기존 내용은 그대로 유지되고, 예전에 등록된 관리자는 모두 대표 관리자가 됩니다.

## 2. 직원 계정 · 권한

**계정 · 연동 → 👥 직원 계정 · 권한** (대표 관리자만)
- `+ 직원 추가` → **아이디** · 이름 · 역할 · 편집할 메뉴 선택 → 계정 만들기. 처음 비밀번호는 한 번만 표시되며 `안내문 복사`로 전달합니다.
- 로그인은 아이디 + 비밀번호입니다 (영문 소문자 · 숫자 · . _ - 3~30자, 대소문자 구분 없음). 예전에 이메일로 만든 계정은 이메일로도 로그인되며, `권한`에서 아이디를 정해주면 아이디로 바뀝니다.
- 역할: **대표 관리자**(전체 + 계정 · 연동 관리) / **관리자**(모든 메뉴 편집) / **담당자**(체크한 메뉴만)
- 권한은 데이터베이스(RLS)에서 강제됩니다. 담당자는 화면을 우회해도 허용되지 않은 메뉴를 수정할 수 없습니다.
- 권한 변경 · 비밀번호 재설정 · 사용 중지 · 삭제 가능. 마지막 대표 관리자는 삭제하거나 낮출 수 없습니다.
- 직원은 **내 계정**에서 이름 · 비밀번호를 바꿉니다.
- 권장: Supabase → Authentication → Providers → Email → **Allow new users to sign up = OFF** (계정은 대표 관리자만 만들도록)

## 3. 업로드 파일 저장소 (GitHub)

관리자에서 올리는 이미지 · 영상 · 첨부파일은 **홈페이지 GitHub 저장소**에 저장됩니다 (Supabase 에 남지 않음).
1. 사이트 저장소가 있는 GitHub 계정 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens → Generate new token**
   - Repository access: **Only select repositories** → 홈페이지 저장소 하나
   - Permissions → Repository permissions → **Contents: Read and write**
2. 관리자 → **연동 설정 → 파일 저장소** → 저장소(`계정/저장소이름`) · 토큰 입력 → `저장하고 연결 확인`
3. 예전에 Supabase 에 올린 파일이 있으면 같은 화면의 **기존 Supabase 파일 → GitHub 로 옮기기** → `지금 옮기기`
   (모든 글 · 번역의 주소를 새 주소로 바꾸고 Supabase 원본은 삭제합니다. 다시 번역하지 않습니다.)

- 파일은 `uploads/<메뉴>/<연>/<월>/…` 에 저장되고 사이트에서는 `./uploads/…` 로 쓰입니다 (기존 `./img` 와 같은 방식). 사이트 반영까지 약 1분이며, 관리자 미리보기는 바로 보입니다.
- 4MB 넘는 파일은 Supabase 임시 위치를 잠깐 거쳐 GitHub 로 옮긴 뒤 바로 삭제합니다 (Vercel 은 한 번에 약 4.5MB 까지만 받을 수 있음).
- 큰 사진은 올리기 전에 자동으로 줄입니다 (긴 변 2560px). 파일당 최대 50MB.
- GitHub Pages 사이트는 전체 1GB 까지라서, 긴 영상은 YouTube · Vimeo 링크를 권장합니다.
- 업로드할 때마다 저장소에 커밋이 하나씩 생깁니다 (메시지: `CMS 업로드: 파일이름`).

## 4. 기존 사이트 연결

1. 전달받은 사이트 완성본(htu-site.zip)을 서버에 덮어쓰거나, 관리자 **대시보드 → 기존 사이트 연결**에서
   `js/htu-cms-config.js` · `menu3.js` · `js/footer.js` · `index.html` · `news.html` · `notice.html` · `event.html` 을 받아 올립니다.
2. 연결 주소는 `js/htu-cms-config.js` 한 곳에만 있습니다. 관리자에서 받은 파일은 주소가 이미 들어가 있습니다.
   img · video · css 폴더는 그대로 둡니다.
3. **기본 설정 → 기존 사이트 주소**가 실제 도메인(`https://htuglobal.com`)인지 확인합니다.
   내부 뉴스 글·공지 링크와 미리보기에 쓰입니다.

> 관리자에서 문구나 이미지를 바꿀 때는 파일을 다시 받을 필요가 없습니다. 파일을 다시 받는 건 섹션 디자인(코드)을 바꿨을 때뿐입니다.

## 다국어 (최대 20개 언어 자동 번역 · 접속 국가별 자동 언어)

관리자에서 **한국어로만** 저장하면 영어·중국어·일본어가 자동으로 만들어지고, 사이트 헤더의 🌐 버튼에서 언어를 고르면 그 언어로 보입니다.

**자동 번역되는 것**
- 관리자에서 관리하는 모든 글: 섹션 문구, 슬라이드, 로고 설명, 출간물, 연재, 영상 제목, News & Event, 공지사항, 이벤트, 팝업, 헤더·푸터 메뉴, 푸터 정보
- 회사소개 · 대표 인사말 등 HTML 에 직접 쓰인 페이지 문구와 버튼 문구 (처음 방문할 때 한 번 번역 후 저장)

**설정**
1. 관리자 → **연동 설정**에서 번역 엔진 API 키 저장 → `연결 테스트`
2. 사이트에 `js/htu-i18n.js` 를 올리고 `menu3.js`, `js/footer.js`, `index.html`, `news.html`, `notice.html`, `event.html` 을 새 버전으로 교체
   (관리자 대시보드 → 사이트 연동 파일에서 내려받거나 htu-site.zip 사용. 언어 목록을 늘린 뒤에는 `js/htu-i18n.js` 도 새로 받아 올리세요)
3. 관리자 → **다국어 → 🌐 번역 · 언어** → `지금 전체 번역` 한 번 실행
4. 매일 새벽 3시 자동 점검은 별도 설정 없이 동작합니다.

**동작 방식**
- 저장할 때마다 바뀐 한국어 문구만 골라 번역합니다 (나머지는 그대로 → 비용 최소).
- 번역을 직접 고치면 **잠금**되어 자동 번역이 덮어쓰지 않습니다. 한국어 원문이 바뀌면 ‘검토 필요’로 표시됩니다.
- 번역 용어집에 `한국어 = 번역어` 형식으로 회사명·브랜드명을 적어두면 그대로 지켜집니다.
- 이미지 안에 들어간 글자는 번역되지 않습니다. 필요하면 언어별 이미지를 따로 만드세요.

**접속 국가별 자동 언어**
- 처음 방문하면 Vercel 이 알려주는 접속 국가로 언어를 정합니다: 한국 → 한국어, 일본 → 일본어, 베트남 → 베트남어, 대만·홍콩 → 번체, 브라질 → 포르투갈어 …
- 그 나라 언어가 꺼져 있으면 브라우저 언어 → 영어 순으로 대신 보여줍니다.
- 방문자가 🌐 메뉴에서 직접 고른 언어는 항상 우선하고 계속 유지됩니다. 자동 선택 결과는 7일마다 다시 확인합니다.
- 관리자 → 번역 관리 → 사이트 언어에서: 사용할 언어 켜기/끄기(20개), 자동 선택 방식(국가 · 브라우저 · 항상 한국어), 국가별 예외(`SG = zh`).
- 지원 언어: 한국어, 영어, 일본어, 중국어(간체·번체), 베트남어, 태국어, 인도네시아어, 말레이어, 필리핀어, 힌디어, 몽골어, 러시아어, 우즈베크어, 스페인어, 포르투갈어, 프랑스어, 독일어, 아랍어, 튀르키예어.
  언어를 더 추가하려면 `lib/i18n/langs.js` 의 목록에 한 줄 추가하면 관리자 · 사이트 모두 자동 반영됩니다.
- DeepL 은 베트남어·태국어·말레이어·필리핀어·힌디어·몽골어·우즈베크어를 지원하지 않습니다. DeepL 을 쓰면 이 언어들은 연동 설정에 Google 또는 Claude 키가 함께 있을 때 자동으로 그 엔진을 사용합니다.
- 여러 언어를 동시에 번역합니다 (기본 4개 언어 동시).
